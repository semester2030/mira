# اختبارات القبول والتسليم
استخدم أدوات المشروع الحالية وبيانات اختبار مصرح بها. وثّق ما استُخدم: تشغيل محلي/اختبار تكاملي/محاكي/جهاز حقيقي. لا تستبدل إثبات الربط بصور تصميمية. الأولوية للمسارات التالية:

| الحالة | الدليل المطلوب |
|---|---|
| أ. استيراد الدليل | مطابقة ٢٢ نوع مقدّم و٧٤ معرّف خدمة و٣٢/٤٢ للتقسيم. لا ازدواج بعد تشغيل الترحيل مرتين ولا إعادة استخدام للرموز المحذوفة. كل خدمة لها مرجع مقدّم وحقول ونص صالح. |
| ب. النطاق | لا تسجيل أو نشر أو اقتراح للأسنان والحقن والليزر الطبي والتقشير العميق. اختبر الاختيار وأيضًا كتابة وصف مخصص لخدمة محظورة ومسار اقتراح خدمة. لا تعتمد على حظر حروف مثل «عيادة» في اسم المؤسسة. |
| ج. المسار الأول الكامل | منشأة «مركز عناية» تختار التنظيف والترطيب في البوابة؛ الخدمة الأولى شرح فقط والثانية بمعرض. بعد النشر: إعلان واحد في اكتشفي، وتفاصيل الخدمتين تعرض البيانات المنشورة نفسها. تعديل الوصف ينعكس بعد التحديث، وإيقافها يمنع حجزًا جديدًا ولا يمس السابق. |
| د. الملكية والتوافق | مقدّمان لنفس الخدمة بأسعار مختلفة لا يطلع أحدهما على مسودات/حجوزات الآخر. عرض قديم ناقص حقولًا ما زال يفتح. لا يظهر سعر مجهول بوصفه «مجانيًا». |
| هـ. الوسائط | جرّب فعليًا حدود نمطي الإعلان ٣ فيديوهات و١ فيديو + ١٠ صور، ورفض ما يتجاوزهما؛ صيغ معرض الخدمة الاختيارية الخمس؛ تحميل/عرض وفشل ثم إعادة محاولة. دوّن ما تم بعينات وسائط حقيقية وما تم باختبار عقد. |
| و. المنتجات | منتج أزياء يغيّر المتغير ثم يضيف الصحيح للسلة. قطعة مجوهرات تفصل وزن المعدن عن الحجر ومقاس الخاتم ولا تخترع شهادة. مستحضر تجميل يعرض درجته أو حجمه بدل S/M/L. اختبر نفاد المتغير وغياب صورة. |
| ز. الحجز المتعدد | مقدّم ذو ٢٠ خدمة تجريبية متاحة في الدليل ضمن أهليته (مثل صالون متعدد الخدمات، لا عشرين إجراءً للبشرة). اختاري خدمتين، احجزي متتاليتين إذا أمكن أو بفترتين. جرّبي اختفاء أحد الموعدين عند التأكيد والضغط المزدوج؛ لا حجز مكرر أو صامت لبند دون الآخر. |
| ح. المناسبة | حالة ٨٠ ضيفة: باقة مع مشمولات + إضافة مدفوعة من القاعة + مصوّرة مستقلة. تحقق من الإجمالي وتغير الكمية وحالة «بانتظار الرد» المستقلة؛ رفض المصوّرة لا يلغي حجز القاعة. |
| ط. المستشارة | فتح من خدمة ثم من مجوهرات ثم من مناسبة يُغيّر السؤال والاقتراحات. «هل الورد مشمول؟» جوابه من الباقة المحددة، أو «لم يذكره المقدّم». المنتج البديل يفتح عنصرًا منشورًا، وعدم وجود مطابق لا ينتج رابطًا. اختبر كتابة حرة، إرفاق صورة، ضغط اقتراح، خطأ مزوّد، وإعادة المحاولة دون تكرار. تأكد من عزل تاريخ عميلتين. |
| ي. واجهات حقيقية | Flutter والبوابة يتصلان بالخادم نفسه في بيئة اختبار؛ لقطات RTL لمقاس صغير وسطح مكتب، وتسجيل مختصر من النشر إلى الجوال. الحالات التجريبية أو التكاملات المعطلة تحمل وصفها الصحيح في التقرير، ولا تُسوَّق كاختبار حي. |

## حزمة الأدلة التي يعيدها Cursor إلى فايز
أنشئ **MIRA-CATALOG-RC1-<short-sha>.zip** وملف **.zip.sha256**. ضع داخل الحزمة:
1. تقريرًا موجزًا لكل حالة: ناجحة / فشلت / لم تُختبر، مع السبب ومسار دليل قابل للفتح، وبيئة التشغيل وSHA. وضّح الفرق بين قبول الحجز والدفع والنشر.
2. جرد الملفات والتغييرات، أو patch للمراجعة إذا لم يكن الفرع متاحًا؛ وقرارات البنية (ما مسؤولية كل وحدة، وكيف تتصل بها بقية الوحدات).
3. مخطط العلاقات والتدفق، عقود API الأساسية مع أمثلة بيانات منزوعة الهوية، خطة الترحيل والتفعيل والتراجع وتوافق النسخ القديمة.
4. دليل مطوّر جديد: تشغيل المشروع وتجربة الرحلة، ثم وصفة عملية لإضافة نوع مقدّم، وخدمة بحقل شرطي وعبارة جاهزة وأيقونة، واختبار ظهورها في الويب والتطبيق والمستشارة. بيّن أي تغييرات تحتاج إصدار تطبيق وأيها تعتمد على البيانات فقط.
5. أدلة الاختبارات واللقطات/التسجيل، وسجل الثغرات الوظيفية المتبقية بالمسؤول والخطوة التالية. لا تدرج أسرارًا أو بيانات عميلات أو ملفات البيئة أو مخازن الوسائط أو مجلدات التبعيات. اختبر صلاحية ZIP وتحقق من البصمة بعد إنشائه.

**تعريف الإنجاز:** دليل قابل للتوسعة + بوابة تكتب بيانات حقيقية + API يتحقق منها + Flutter يعرض ويحجز/يشتري حسب النوع + «اسألي ميرا» تجيب عن العرض الحقيقي. إذا اكتمل مسار دون آخر، صف ما اكتمل فقط.
