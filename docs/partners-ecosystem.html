١. القرار المعماري الموصى به

نموذج هجين (Hybrid) — الأنسب لميرا

الفئةتجربة المستخدم (B2C)تجربة الشريك (B2B)
مستخدمة ميرا تطبيق Flutter — اكتشاف، توصيات، حجز، متابعة —
ماركة / عيادة / صالون Deep link من التطبيق عند الحاجة بوابة ويب partners.mira.app — تسجيل، كatalog، مواعيد، تقارير
فريق ميرا — لوحة Admin — اعتماد الشركاء، مراقبة، عمولات

لماذا ليس كل شيء داخل التطبيق؟

  • الشركات لديها متاجر Salla / Shopify / Zid — الدفع والمخزون يبقى عندهم.
  • العيادات والصالونات تحتاج تقويم موظفين وإدارة يومية — أسهل على الويب.
  • فصل B2B يقلّل حجم التطبيق ويسرّع موافقة App Store.

لماذa ليس ويب فقط للجميع؟ المستخدمة تتوقع تجربة موحّدة بعد التحليل داخل التطبيق (شاشة 2 و 3 الموجودة).

٤. سيناريوهات تفصيلية

٤.١ ماركة تجميل (Brand) — 10 شركات

السيناريو A — متجر Salla/Shopify (الأكثر شيوعاً)

  1. المستخدمة تنهي التحليل → شاشة التقرير + الروتين.
  2. محرك المطابقة يختار 3–8 منتجات من ماركات معتمدة حسب concernScores.
  3. تضغط «اشتري من المتجر» → Deep link لصفحة المنتج في متجر الماركة + UTM/affiliate.
  4. الشراء والدفع 100% على منصة الماركة.
  5. ميرا تتتبع النقرات والتحويلات عبر webhook أو تقارير affiliate.

لا مخزون في ميرا لا دفع in-app للمنتج أسرع إطلاق

السيناريو B — كatalog داخل ميرا + checkout خارجي

  1. عرض المنتج داخل التطبيق (صورة، سعر، وصف).
  2. «إتمام الطلب» يفتح WebView/Safari لسلة مسبقة التعبئة (cart pre-fill API إن توفر).

السيناريو C — Marketplace كامل (مرحلة متقدمة)

سلة موحّدة + دفع (Moyasar/HyperPay) + تقسيم عمولة — يحتاج اتفاقيات وامتثال أعلى.

٤.٢ عيادة تجميل / طبيب

السيناريو — توصية → حجز استشارة

  1. تحليل يظهر: احمرار عالي + حبوب → توصية «استشارة جلدية» + « peel خفيف ».
  2. قائمة عيادات قريبة (GPS أو مدينة من الملف).
  3. اختيار طبيب/عيادة → خدمة → تاريخ → وقت → تأكيد.
  4. إشعار للعيادة (بوابة الشركاء + SMS).
  5. تذكير قبل الموعد 24 ساعة.

ملاحظة طبية: التوصيات «إرشادية» وليست تشخيصاً — disclaimer في كل شاشة.

٤.٣ صالون تجميل

السيناريو — روتين + حجز خدمة

  1. بشرة جافة → سيروم (ماركة) + «جلسة facial ترطيب» (صالون).
  2. اختيار صالون → خدمة (60 د) → stylist اختياري → موعد.
  3. عربون 50 ر.س in-app أو «ادفع في الصالon».
  4. بعد الجلسة: تقييم + نقاط ميرا.

٥. Booking Flow — تدفقات الحجز بالتفصيل

٥.١ حجز عيادة (7 خطوات — 5 شاشات في التطبيق)

1. Discovery ← من skin_routine أو tab «عيادات» 2. Clinic List ← فلتر: مدينة، تقييم، concern 3. Clinic Detail ← أطباء، خدمات، صور، موقع 4. Service Pick ← مدة، سعر، ما قبل الجلسة 5. DateTime ← تقويم من Partner Portal API 6. Confirm ← ملخص + disclaimer + عربون؟ 7. Success ← رقم حجز + إضافة للتقويم
حالة الحجزمن يغيّرها
pendingالمستخدمة — awaiting clinic
confirmedالعيادة — بوابة الشركاء
cancelledأي طرف + سياسة إلغاء
completedالعيادة — بعد الزيارة
no_showالعيادة

٥.٢ حجز صالون (8 خطوات — 6 شاشات)

Discovery → Salon List → Salon Detail → Service → Stylist (optional) → DateTime → Confirm (+ deposit) → Success

٥.٣ طلب منتج ماركة (4 خطوات — 3 شاشات in-app + متجر خارجي)

Matched Products (from report) → Product Detail → «الشراء من المتجر» → External Store Checkout (Salla/Shopify) → (optional) Return deep link + conversion ping

١٠. شاشات تسجيل الشركاء (بوابة الويب)

/register Step 1: نوع الشريك (brand | clinic | salon) Step 2: جوال + OTP (Firebase Auth — نفس infra المستخدمات) Step 3: بيانات قانونية (سجل، ضريبة، رفع PDF) Step 4: الملف العام (اسم، وصف، شعار، مدينة) Step 5: نوع الكatalog brand → import URL أو إدخال منتجات يدوي clinic → خدمات + أطباء + availability salon → خدمات + موظفين + availability Step 6: pending_review → Admin يعتمد → active
