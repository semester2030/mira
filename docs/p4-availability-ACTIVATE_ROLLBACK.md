# تفعيل وتراجع — وثيقة الإتاحة v2 (P4)

## تفعيل
1. انشر الـ commit المختبر فقط بعد نجاح قبول P4 المحلي (slots + acceptance).
2. الوثائق الجديدة تُحفظ كـ `{v:2, timezone:"Asia/Riyadh", windows, closedDates, exceptions}`.
3. القرّاء الحاليون يستخدمون `normalizeAvailabilityDocument` و`windowsForDate` / `resourceIdsFromAvailabilityDocument`؛ لا حاجة لترحيل جماعي للصفوف القديمة (مصفوفة نوافذ فقط تبقى صالحة).

## تراجع آمن للبيانات (لا تجاهل للتقويم)
**غير آمن:** إعادة نشر قارئ يتجاهل `closedDates` و`exceptions` ويعرض/`يقبل` مواعيد من `windows` الأسبوعية وحدها. ذلك يغيّر الإتاحة المعروضة والمقبولة عن الوثيقة المحفوظة.

إجراء التراجع المعتمد:

1. **أبقِ بيانات JSON كما هي** — لا تحذف `closedDates`/`exceptions` ولا تشغّل ترحيلًا مدمّرًا.
2. **إمّا** أبقِ قارئ v2 متوافقًا (نفس دوال التطبيع والحجز) على مسار العرض والحجز معًا،
3. **أو** عطّل مؤقتًا عمليات الحجز/عرض المواعيد المتأثرة أثناء نافذة التراجع (feature flag / إيقاف `bookingEnabled` التشغيلي) حتى يعود قارئ متوافق.
4. لا تعتبر «تجاهل الحقول الإضافية» تراجعًا آمنًا لواجهة الحجز أو `createBooking`.
5. محرر قديم يعرض النوافذ فقط دون تقويم الإغلاق يُسمح به للقراءة الإدارية فقط إذا وُسم صراحةً بأنه غير مصدر للحجز؛ مصدر الحجز يجب أن يبقى قارئ v2 أو متوقفًا.

## تحقق سريع بعد التراجع
- يوم في `closedDates` → لا slots ولا قبول حجز.
- `exceptions.kind=special` → الساعات المعروضة/المقبولة من الاستثناء وليست من الأسبوع المستبدل.
- مورد في فترة خاصة فقط → يظهر في العرض ويُقبل عند استيفاء الشروط (اتساق list≡book).
