# ميرا | التسجيل وصلاحيات نشاط الشريك
**تسليم محلي قابل للتشغيل، وليس إصدارًا منشورًا.** ينفذ نموذج تسجيل، متابعة الطلب، إدارة البنود، شاشة الملف وطلب التوسعة، وتفويض كتابة من جهة الخادم. الأصول تخص مشروع ميرا؛ قاعدة العرض المحلية منفصلة عن بيانات الشركاء الفعلية. البيانات المحلية لا تذهب إلى الموقع أو التطبيق.

## تشغيل سريع
يتطلب Node 22.13 أو أحدث (اختُبر بـ Node 24). بعد فك الضغط ادخل إلى مجلد partner-activities:
```bash
node --test test/*.test.mjs
node server/local.mjs
```
افتح http://127.0.0.1:4317/apply.html . الخادم يستمع للعنوان المحلي فقط. لا توجد تبعيات npm مطلوبة للعرض. يستخدم SQLite ويحفظ الطلبات في ملف local-test.sqlite في مجلد التشغيل. لا تضع بيانات حقيقية فيه.
- املأ نموذج الانضمام كمتجر/براند/صالون/مستقلة/عيادة/منظم مناسبات (اختيارات متعددة)، وصف النشاط، المدينة، ودليل العمل عند توفره. اختر أماكن تقديم الخدمة: في المقر، استوديو مقدمة الخدمة، منزل العميلة أو عن بعد.
- افتح /status لمتابعة طلبك. في النسخة المحلية تدخلين بياناتك دون تنشيط المحرر قبل الموافقة. في النظام الفعلي ينبغي إبقاء آلية متابعة الطلب الرسمية بما فيها statusToken إن كانت مستخدمة.
- افتح /review في نافذة مستقلة وسجل الدخول بحساب admin@local.test وكلمة مرور الاختبار التي يعرضها الخادم محليًا في الطرفية. حدّد البنود التي راجعتها. الاعتماد يحتاج توثيقًا لكيفية التحقق، والرفض/الاعتماد الجزئي يحتاج سببًا. يسجل الخادم المراجع والقرار والوقت.
- عند اعتماد بند واحد على الأقل يُفعّل حساب الشريك. افتح /profile بحسابه، راجع المعتمد، أضف/عدّل عرضًا، ثم اطلب التوسعة. يبقى المعتمد القديم متاحًا. طلب التوسعة المرفوض لا يغيّر المعتمد. لمنع ازدواج القرار يسمح بطلب توسعة معلق واحد؛ يمكن إعادة التقديم بعد القرار.
- المطور: developer@local.test وكلمة مرور مستقلة في الطرفية. هذه الهوية للاختبار المحلي فقط؛ لا يظهر اختيار «مطور» في التسجيل العام. تمنحه صلاحية كل أصناف المنتجات والخدمات. المراجعة الإدارية تنفذ باختصاص الإدارة.
- حساب الشريك لا يرتبط بعدد القطع المباعة: النطاق «منتج بالاسم» يحد العرض إلى هوية واحدة عبر المسودة والتعديل والنشر، بينما «التصنيف» يسمح بعدة عروض في الفرع نفسه. لقبول عدة منتجات محددة من نفس الفرع أدخل اسم كل منتج في سطر مستقل. اعتماد كل فروع المجموعة يثبّت الفروع المحددة في وقت القرار ولا يشمل فروعًا مستقبلية تلقائيًا.

## ما الذي جُرّب؟
راجِع docs/test-results.txt. تشمل الاختبارات السجل الفعلي المحلي، عدم النشر قبل الموافقة، منع تبديل النشاط عند التحرير، رفض استخدام نشاط شريك آخر، براند منتج واحد، متجر متعدد، صلاحية المطور، اعتماد متزامن واحد، تراجع التغييرات عند فشل الكتابة، ورحلة HTTP كاملة من التسجيل حتى التوسعة والنشر المحلي. هذه اختبارات لخادم الوحدة وواجهاته؛ لا تتضمن اختبارًا بصريًا على آيفون، تشغيل PostgreSQL/Prisma على ميرا، أو اختبار Render.

## الملفات
- server/model.mjs: قواعد الطلب والقرار والمنح والتحقق عند الكتابة. لا يقرأ دور المطور أو صاحب العنصر من نموذج المستخدم.
- server/schema.sql: مخطط إضافي للطلبات والبنود والمنح والسجل. لا يحذف جداول ميرا.
- server/production-mount.mjs + prisma.mjs: نقاط ربط API وPrisma للنظام القائم، تتطلب تزويدها بجلسات ومحررات وتفعيل الحساب الرسمي. لا تُستخدم هوية العرض المحلي في الإنتاج.
- server/db.mjs: SQLite للاختبار، ومحوّل pg إن كان مضيف مختلف يستخدم pg أصلًا. استعمل Prisma الموجود في ميرا ولا تنشئ مخزنًا ثانيًا للمنح.
- server/local-host.mjs + local.mjs + catalog.fixture.mjs: تسجيل دخول وكتالوج ومحرر مبسّط لاختبار العقد محليًا فقط.
- web/: واجهة عربية للتسجيل، الإدارة، الملف، متابعة الطلب واختبار الحفظ. الحقول الخاصة بالمجوهرات لم تتغير. احتفظ بالمحرر الرسمي الأفقي، الوسائط، الخيارات والمواعيد عند الدمج.
- docs/INTEGRATE.md: الربط بالمسارات الحقيقية والترحيل والقبول قبل النشر.
