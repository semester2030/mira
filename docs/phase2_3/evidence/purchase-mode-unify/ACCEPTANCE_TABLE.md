# توحيد طريقة طلب المنتج — جدول القبول

| اختيار البائع | القيمة المحفوظة (`purchaseMode`) | ما ظهر عند إعادة الفتح | زر العميلة ونتيجة الضغط |
|---|---|---|---|
| عرض فقط | `display` | الخيار «عرض فقط» محدّد؛ بلا رابط ظاهر | لا زر شراء/تواصل على الفيديو؛ رسالة عرض فقط |
| شراء داخل ميرا · الدفع عند الاستلام | `internal_cod` | نفس الخيار + حقول الكمية/رسوم التوصيل | «أضيفي للسلة» → سلة ميرا → طلب MO عند إتمام الدفع عند الاستلام |
| شراء من متجر خارجي | `external` (+ `externalUrl` صالح) | نفس الخيار + حقل الرابط معبأ | زر متجر البائع → فتح رابط خارجي (ليس طلب ميرا) |
| تواصل للاستفسار | `contact` | نفس الخيار + وسيلة تواصل الشريك | «تواصلي» → `tel:` (ليس طلب شراء) |

## ملاحظات تحقق

- **API:** `commerce-public.schema-tests` تمرّ؛ `display`/`contact` مقبولان في DTO؛ السجلات القديمة `external` بلا رابط تُعرض للعميلة كـ `display` دون تعديل الصف.
- **بوابة الإنتاج:** بعد نشر `purchase-mode1` — جلسة جديدة / تحديث قوي.
- **التطبيق:** مسارات `decideBuyRoute` تميّز الأوضاع الأربعة؛ التحقق الكامل لرحلة MO على جهاز يتطلب منتجًا تجريبيًا معزولًا (لم تُمسّ منتجات ميرا الحقيقية).
- **قبل:** راديو «بدون شراء / رابط / تواصل» + مربع «تفعيل الطلب داخل ميرا» متعارضان.
- **بعد:** سؤال واحد «كيف تطلب العميلة هذا المنتج؟» بأربعة اختيارات حصرية ومعاينة فورية.
