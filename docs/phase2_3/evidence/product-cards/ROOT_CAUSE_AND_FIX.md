# بطاقات منتجاتي — حالة واضحة وإجراءات حسب الصلاحية

## معنى `withdrawn` في النظام
`DELETE /partners-portal/products/:id` ليس حذفًا نهائيًا: يضبط `active=false` و`contentStatus=withdrawn` (إيقاف عرض / أرشفة ناعمة). يبقى الصف في قاعدة البيانات وسجل الطلبات.

## ما كان خاطئًا
- زر «سحب» يظهر لكل البطاقات بما فيها المسحوبة أصلًا.
- الحالة تُعرض بقيم تقنية (`published` / `withdrawn`).
- «فتح في النموذج» غير مفهومة للبائع.
- إعادة النشر بعد السحب كانت تفشل في مسار الاعتماد لأن `decide` يرفض الصفوف `withdrawn`.

## الإصلاح
- بطاقة حسب الحالة: منشور / متوقف / مسودة / قيد المراجعة (+ شارة تعديلات غير منشورة).
- إجراءات: تعديل · إيقاف العرض · إعادة النشر / إرسال للمراجعة · حذف المسودة · المزيد (أرشفة / حذف تعديلات غير منشورة).
- إيقاف إداري (`reviewedBy` غير شريك): بلا إعادة نشر.
- API: السماح باعتماد صف `withdrawn` بعد `submit-review`؛ مسار `discard-pending-edits` للنسخة المنشورة.

## اختبارات محلية (mock ميرا)
انظر `CARD_STATES.json` و`ACTIONS.json` والقطات `02`–`06`.
- إيقاف «فستان سهرة» → `stopped` عبر DELETE.
- إعادة نشر «فستان زواج» → `published` عبر submit-review.
- تعديل يفتح نفس الاسم في المحرر.
