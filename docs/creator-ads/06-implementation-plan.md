# 06 — خطة التنفيذ والاختبار

الاعتماديات بين المراحل خطية في الغالب: **وسائط إعلان → شراء/حجز بإسناد → تقارير → صفحة مشهور/روابط**. لا يُكسر الكتالوج أو الطلبات الحالية بإضافة حقول اختيارية `adId?`.

## مرحلة 0 — مواءمة المنتج (بدون كود إلزامي)

| | |
|---|---|
| النطاق | حسم قرارات [04](./04-attribution-rules.md) القسم ز؛ تصحيح فهم أن `CatalogAd` موجود |
| المخاطر | بناء وسائط/إسناد على افتراضات خاطئة |
| قبول | قرارات موثّقة في ISSUE/DEC قصيرة تشير لهذا المجلد |

## مرحلة 1 — وسائط إعلان مستقلة

| | |
|---|---|
| النطاق | `ownerKind=ad`، مسارات رفع/ترتيب، محرر بوابة، `publicBody.media` من الإعلان لا من الهدف؛ منع حذف أصل التاجر |
| وحدات | `mira-api` media/ad؛ `partners-portal` ads؛ Discover يستهلك الوسائط كما هي |
| مخاطر | خلط مفاتيح التخزين؛ نشر قبل اكتمال الملفات |
| اختبارات | وحدة سياسة الحدود؛ HTTP رفع لإعلان؛ انحدار أن حذف وسيط إعلان لا يمس منتجًا |
| قبول | حالتي **٣ فيديوهات** و**فيديو+حتى ١٠ صور** تعملان على إعلان منشور وتُشاهدان في العميل |
| إطلاق تدريجي | مطوّر أولًا؛ feature flag إن لزم؛ رجوع = الإبقاء على سقوط وسائط الهدف مؤقتًا خلف علم |

## مرحلة 2 — إسناد بند الشراء والحجز

| | |
|---|---|
| النطاق | `adId` اختياري على cart item / order item / booking؛ تحقق خادمي؛ Discover/التفاصيل يمرّران `adId`؛ تفعيل مساري COD/حجز من شريحة الإعلان عندما يكون العرض داخليًا |
| يعتمد على | مرحلة 1 إن أردنا رحلة كاملة؛ يمكن بدء التحقق بلا وسائط |
| مخاطر | دمج سلة يكسر المصادر؛ طلبات قديمة بلا عمود |
| اختبارات | مثال الطلب المختلط؛ إرجاع جزئي؛ حجز مؤكد→ملغى؛ idempotency |
| قبول | أرقام [04](./04-attribution-rules.md) مثال القبول تتحقق من API |
| رجوع | تجاهل `adId` إن العلم مغلق؛ الأعمدة تبقى nullable |

## مرحلة 3 — التقارير من مصدر واحد

| | |
|---|---|
| النطاق | insights مشهور + تفصيل تاجر؛ إعادة بناء من البنود؛ منع قراءة عبر الشركاء |
| يعتمد على | مرحلة 2 |
| اختبارات | تكرار إشعار؛ شريك أ لا يقرأ ب؛ اتحاد المشترين عبر إعلانات |
| قبول | تطابق تقرير الطرفين على نفس الطلب المختلط |

## مرحلة 4 — صفحة مشهور عامة والروابط

| | |
|---|---|
| النطاق | صفحة عامة قابلة للمشاركة؛ روابط قنوات؛ الحفاظ على السياق بدون تطبيق |
| يعتمد على | 1 على الأقل لعرض ذي معنى |
| قبول | مشاركة رابط يفتح إعلانات المشهور؛ موضع أيقونة المشاهير قرار تصميم مفتوح |

## مصفوفة سيناريوهات يجب أن تغطيها الاختبارات (منفّذ vs مقترح)

| سيناريو | منفّذ الآن | مقترح |
|---|---|---|
| مشهور يعلن فقط (بدون متجر) | ربط هدف منشور | + وسائط + إسناد |
| يقدّم خدمة فقط / يجمع النشاطين | أنواع partner قائمة | أسطح store/provider |
| يعلن للغير | ممكن بلا إذن تاجر صريح | + DEC إذن |
| عدة مشاهير لنفس العرض | عدة `CatalogAd` | تقارير منفصلة |
| عدة إعلانات لنفس المشهور لنفس العرض | عدة صفوف | كل بإسناد ووسائط |
| ٣ فيديوهات / فيديو+١٠ صور | غير متحقق للإعلان | مرحلة 1 |
| طلب مختلط + إرجاع جزئي | غير موجود كإسناد | مرحلة 2–3 |
| حجز مؤكد ثم ملغى | حجوزات عامة بلا ad | مرحلة 2–3 |
| حدث مكرر link-open | idempotent eventId **مغطى جزئيًا** | الإبقاء |
| شريك يقرأ مبيعات آخر | حارس قائمة إعلانات | اختبار رفض insights |
| رجوع من تفاصيل دون فقد السياق | جزئي في Discover | تثبيت مع صفحة مشهور |
